# Outreach and validation

**Nothing has been collected yet. This file is empty on purpose.**

As of **Thu Sep 17, 2026**, no parent, clinician, researcher, advocate, studio or
app maker outside this project has seen Calm Frames, used it, or said anything
about it. There are no quotes on this page because there are none to put here.

This file exists so that when a reply does arrive it has somewhere to go that
records who said it, when, and what they agreed to. It also exists so that
nobody reading the README has to wonder whether the impact section rests on
feedback we do not have. It does not.

## The rules this page runs on

These are not optional and they are not a formality.

1. **No invented quotes, ever.** Not as an example, not as a placeholder, not
   greyed out, not marked "illustrative". If a line of text is on this page in
   quotation marks, a real person said it. There are no sample rows below for
   exactly this reason.
2. **No composite people.** The persona in `docs/SUBMISSION.md` is labelled a
   composite where it appears, and it never appears here. This page holds
   named, real, consenting sources or it holds nothing.
3. **Consent before publication, in writing, per quote.** A reply to an email is
   not permission to publish it. Ask, get a yes, record the date of the yes, and
   record exactly what was agreed: name and affiliation, first name only,
   role only, or anonymous.
4. **No endorsement is implied or reported.** Every outreach draft says plainly
   that we have no measurements and there is nothing to approve. A reply about
   wording is feedback on wording. Writing it up as support for the project
   would misrepresent the person who sent it.
5. **Withdrawal is honoured immediately.** Anyone who changes their mind has
   their entry removed from this file and from anything built from it, including
   the README, the Devpost text and the video, with no discussion.
6. **Nothing we send contains flashing.** That holds for every exchange on this
   page. No clips, no images, no links to either. `docs/SAFETY.md` applies to
   outreach as much as to the media pool.

## Collected feedback

**None.**

When there is some, one entry per reply, in this shape:

| Field | What goes in it |
|---|---|
| Date received | The date the reply arrived |
| Who | Exactly as much as they agreed to be identified by, and no more |
| What they were asked | Usually: does the safety sentence overstate what a tool like this can do |
| What they said | Their words, quoted, not summarized into something stronger |
| Consent | The date they agreed in writing, and what form they agreed to |
| What changed | The commit or the file that changed because of it, or "nothing changed, and why" |

The last field matters more than it looks. Feedback that changed nothing is worth
recording as feedback that changed nothing. Feedback quietly dropped because it
was inconvenient is the failure this whole page is built to prevent.

## What we would still not be able to claim

Even with three warm replies in hand, this project would not be validated. It
would be three people's opinion of one sentence. Worth having, and not the same
thing.

What would count as validation is in `docs/EVAL_PLAN.md` and none of it has
happened: blind labelling of the 40 real segments by two labellers, a cover lead
time measured on a physical stick at 240 fps, and a conformance run that is not
partial. Those are measurements. This page is correspondence.

The approved wording does not change whatever anyone replies: **Calm Frames
reduces exposure to flashing above published limits in the videos it plays; not
a medical device.**
