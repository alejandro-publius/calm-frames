## Smallest useful next video path, not implemented here

`pipeline.local_library prepare` already accepts a local video and an existing private/public signer pair, analyzes all three presets, renders prepared media and produces a verification-bound receipt. `pipeline.packaged_library export` rechecks signatures and bytes and creates the exact compiled title/preset membership; pre/post build gates verify package contents. The upload web page is report-only: it deletes the uploaded clip and does not add it to the TV shelf.

For one chosen non-DRM video: confirm input rights/format, reuse an explicitly authorized existing signer, prepare in a fresh local workspace, inspect the complete report, export to a fresh reviewed bundle, approve that exact catalog membership, replace Home's explicit Acadia-only filter with a reviewed selection of packaged titles, and build/install/check the native flow. Do not add an arbitrary-route key or catalog URL. Existing trust authorizes the current Acadia bundle only, so a new bundle still needs explicit review; possession of the same public key is insufficient. No credentials were inspected in this pass and signer availability is unverified. Package bounds are 16 titles / 64 MiB including retained generations; a longer video may need a separately designed delivery path.

This is a bounded integration task for one short file with an available authorized signer, not a new analyzer. Consumer self-service needs a file picker/upload and progress/error flow, preparation service or desktop companion, authenticated delivery, persistent library management, and an explicit trust/onboarding design. That is a separate feature, with larger security, storage and native lifecycle work. Neither path filters other apps.
